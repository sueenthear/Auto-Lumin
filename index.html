Capabilities

从看见画面，到完成动作

一套 Python API 覆盖窗口、图像、声音与输入回放；启动器负责环境、任务和进程。你只需要写脚本。

窗口绑定

按进程名或窗口标题绑定目标，坐标始终基于客户区，窗口移动也不会影响操作。

图像与像素

模板匹配返回最佳中心坐标，支持 ROI 与三种算法；像素计数可做快速颜色判断。

声音触发

只监听绑定进程的声音，提示音越过阈值即执行动作；不混入系统混音与其他程序。

动作录制与回放

开发工具录制真实键鼠时序，导出 .stepscript；脚本中加载后后台回放，可暂停、继续或中止。

任务启动器

递归扫描 Task/ 下所有 this.task，分类、搜索、按修改时间排序，一键进入详情与运行。

日志与中断

运行页分栏显示调试 log 与普通输出；F12 全局中断立即结束进程，运行期间禁止误返回。

Interface

四页工作流，克制而清楚

启动页只做检查，任务页只做选择，详情页确认后才会运行。浅色与深色主题都跟随系统级质感。

Deployment

五步完成部署

启动器只是入口，运行任务还需要工作区环境。全部命令在项目根目录执行。

环境清单

缺一项，启动页都会标红并阻止进入任务。

Python≥ 3.10
uv 包管理器最新版
Git for Windows含 Git Bash
WindowsBuild ≥ 20348
权限管理员
获取 AutoLumin.exe

  1. 准备运行环境

    安装 Python 3.10+、uv 与 Git for Windows。Git Bash 是启动器激活虚拟环境的必要组件，不能用 WSL 的 bash 替代。

    PowerShell
    uv --version
git --version

  2. 获取工作区

    克隆仓库，或下载完整工作区。启动器需要与 pyproject.toml、uv.lock、script_core 和 Task 同级。

    PowerShell
    git clone https://github.com/sueenthear/Auto-Lumin.git
cd Auto-Lumin

  3. 安装依赖

    按锁文件同步依赖，并把 script_core 以 editable 方式挂载到工作区虚拟环境。

    PowerShell
    uv sync --locked

  4. 放入启动器并运行

    把 AutoLumin.exe 放到工作区根目录，双击启动。程序会请求管理员权限，六项检查全部通过后点击“进入任务”。

    目录结构
    Auto-Lumin/
├─ AutoLumin.exe
├─ pyproject.toml
├─ uv.lock
├─ script_core/
├─ Task/
└─ .venv/

  5. 添加你的任务

    在 Task/ 下任意层级的文件夹中放入 this.task 与运行脚本，重新扫描即可出现在任务页。

    任务目录
    Task/日常/采集/
├─ this.task
├─ run.py
└─ 说明.png

Scripting

一个文件夹，就是一支脚本

用 this.task 描述任务，用 run.py 写流程。启动器会激活工作区环境，以 run.py 所在目录为工作目录。

Task/
├─ 日常/
│  └─ 采集/
│     ├─ this.task      # 任务描述
│     ├─ run.py         # 运行入口
│     └─ 说明.png       # 可选说明图
└─ 周常/
   └─ 副本/
      ├─ this.task
      └─ run.py
title
任务名称，显示在列表、详情与运行页。
description
文字说明，可省略；用于搜索与详情页展示。
run_target
相对于 this.task 的 Python 文件，默认 run.py。
description_image
可选说明图，只支持 .png，留空表示无图。
editor / version
作者与版本，显示在任务卡片右侧。
任务路径必须是相对 this.task 的路径，且不能越出工作区。全局 F12 会直接结束进程，不会执行 finally 清理。
JSON
{
  "title": "每日采集",
  "description": "按固定路线完成每日采集。",
  "editor": "your-name",
  "version": "1.0",
  "run_target": "run.py",
  "description_image": "说明.png"
}
from script_core import Core

do = Core("Lumin.exe", timeout=10)   # 按进程名绑定窗口
do.thisfile                          # 工作目录切到脚本所在目录
do.window.activate()                 # 恢复最小化并置于前台

if do.match.exist("claim.png", threshold=0.9):
    do.mouse.click.left              # 属性访问即执行
    do.wait(0.6)

actions = do.steps.load("actions.stepscript")
do.steps.start(actions)
do.steps.wait(actions)

if actions.error is not None:
    raise actions.error
def on_sound():
    do.keyboard.click("shift")       # 匹配到提示音后执行

do.audio.action(on_sound)
do.audio.listen.threshold(0.35)      # 阈值 (0, 1]
do.audio.listen.start()              # 只监听目标进程

while True:
    do.wait(1)                       # 保活；F12 全局中断

FAQ

开始之前

几个最常见的疑问。其余问题可以直接在群里问。

需要管理员权限吗？
目标游戏以管理员身份运行时，启动器和脚本也需要同等权限，否则 Windows 会阻止窗口操作与输入注入。启动器启动时会自动请求提权。
支持哪些 Windows 版本？
需要 Windows 10 Build 20348 及以上或 Windows 11。声音匹配依赖 Windows 进程独立 loopback，低版本会直接报错，不会退回系统混音。
启动器报“缺少工作区”怎么办？
确认 AutoLumin.exe 位于包含 pyproject.toml、uv.lock、script_core 与 Task 的目录中，并已执行 uv sync --locked；也可以在启动页手动选择工作区。
任务脚本从哪里来？
可以加入 QQ 群 1108948355 获取现成脚本，也可以按上面的结构自己写。每个任务只是一个文件夹：this.task + run.py。
日志太多，能关掉调试输出吗？
详情页勾选“运行时不输出用于开发调试的 log”即可隐藏 log 面板，只保留普通输出与错误信息；重新运行会沿用本次选择。
