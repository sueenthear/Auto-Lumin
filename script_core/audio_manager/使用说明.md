# audio_manager 使用说明

按声音触发自动化操作：只监听 `Core(...)` 绑定窗口所属进程及其子进程播放的音频，不采集系统混音，也不采集其他程序。

---

## 1. 前置条件

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10 Build 20348 及以上（`sys.getwindowsversion().build >= 20348`） |
| Python | 3.10+，项目 `.venv` 已装好依赖（`uv sync`） |
| 权限 | 与目标游戏同级；游戏以管理员运行时，本脚本也要以管理员运行 |

不满足系统版本时直接抛 `RuntimeError`，**不会**退回系统混音——那会把其他程序的声音也算进去，无法保证只对目标 exe 生效。

---

## 2. 快速上手

```python
from script_core import Core

do = Core("Lumin.exe", timeout=10)

def dodge():
    do.keyboard.click("SPACE")

do.audio.action(dodge)      # 匹配成功后调用，必须是无参数函数
do.audio.listen.start()     # 不传路径：自动查找 template.voice
```

脚本运行期间后台线程持续采集、比对；按 `F12`（默认中断键）结束进程。

停止监听：

```python
do.audio.listen.stop()
```

## 3. 制作模板（录制工具）

模板文件是扩展名为 `.voice` 的标准 WAV（16 kHz、单声道、16 位 PCM），可直接用普通播放器试听。

### 3.1 启动

双击项目根目录的 `启动录音剪辑工具.bat`，或在项目根目录执行：

```powershell
uv run python -m dev_tool.audio_recorder
```

`.bat` 会以管理员权限启动 `dev_tool.audio_recorder`，工作目录固定为项目根目录。游戏以管理员运行时必须用这种方式，否则采集不到目标进程的音频。

### 3.2 录制

1. 「目标 exe」填可执行文件名，例如 `Lumin.exe`，点「绑定」；状态栏出现 `已绑定 ... (PID xxxx)` 即成功。
2. 「最长录制秒数」填 0.04–10 之间的值（默认 10）。
3. 「录制输出」确认路径，扩展名必须是 `.voice`。
4. 让游戏播放目标提示音，按 **F8** 开始录制。
5. 按 **F9** 结束并保存。达到最长秒数也会自动结束。

录完会立刻载入下方编辑区。

### 3.3 试听与剪辑

- 「试听整段」播放整个文件。
- 填「起始」「结束」秒数后点「试听剪辑」，只播放这一段。
- 「试听停止」中断播放。
- 「保存剪辑为 .voice」把选中区间另存为新模板（区间不能短于 0.04 秒）。

### 3.4 让模板成为默认

`do.audio.listen.start()` 不传参数时**只查包内**：

```
script_core/audio_manager/template.voice
```

工作目录里的 `template.voice` 会被忽略——避免脚本目录下一个遗留文件悄悄改变匹配的音效。要让新录的模板成为默认，直接覆盖包内这一份：

```
script_core/audio_manager/template.voice
```

> 录音工具和剪辑保存的默认输出路径已经指向这个包内文件，录完按 F9 保存即生效。
> 若想保留原模板，先手动备份，或在保存时改「录制输出」路径。

不想动包内文件时，显式传路径即可：

```python
do.audio.listen.start(r"D:\templates\dodge.voice")
```

## 4. API 参考

### `do.audio.action(func)`

注册匹配成功后调用的**无参数**可调用对象。传非可调用对象抛 `TypeError`。

动作在独立线程执行，因此内部可以放心调用 `do.keyboard.*`、`do.mouse.*`、`do.wait()` 等阻塞接口。同一时间只会有一个动作在跑，上一动作未结束时新触发会被跳过。

### `do.audio.listen.threshold(value)`

相似度阈值，取值范围 `(0, 1]`，默认 `0.8`。非法值（含布尔、`nan`、`inf`）抛 `ValueError`。

- 调高（如 `0.9`）：更严格，误触发少，但可能漏掉略有变调的提示音。
- 调低（如 `0.6`）：更宽松，容易触发，但不同音效可能互相误判。

监听运行中也可调用，立即对后续音频生效。

### `do.audio.listen.start(template=None)`

开始监听。

- `template=None`：按上文顺序查找默认模板。
- `template="路径.voice"`：使用指定文件。

模板校验（不通过即抛异常，不会启动线程）：

| 校验项 | 要求 |
| --- | --- |
| 扩展名/格式 | RIFF WAV，16 kHz、单声道、16 位 PCM |
| 长度 | 0.04–10 秒 |
| 音量 | 不能是静音（峰值需大于 96） |
| 变化量 | 不能是恒定直流，否则无法比对 |

已在监听时再次调用抛 `RuntimeError("音频监听已经在运行")`。

### `do.audio.listen.stop()`

停止监听并等待线程退出。未在监听时调用是安全的空操作。

### `do.audio.listen.listening`

`bool`，当前是否正在监听。

### `do.audio.listen.error`

最近一次失败原因，正常时为 `None`。这是**属性**，不加括号。

## 5. 触发规则

- 相似度越过阈值即触发一次，然后进入「未武装」状态。
- 重新武装需要满足其一：
  - 约 40 毫秒静音；或
  - 连续一个模板长度的音频都不匹配。
- 因此：**同一个音效连续播放会多次触发**，而一段较长的音效内部不会被切成两次触发。
- 绑定窗口关闭或 PID 变化时，监听自动终止，原因写入 `error`。

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `RuntimeError: 进程独立音频监听仅支持 Windows Build 20348 或更新版本` | 系统版本过低，无法按进程隔离采集。 |
| `RuntimeError: 绑定进程音频监听失败或已停止` | 看 `do.audio.listen.error` 里的原始异常；常见是权限不足（游戏以管理员运行，脚本没提权）或音频设备不可用。 |
| `FileNotFoundError: 尚未提供真实的 template.voice` | 两处默认位置都没有模板，用录音工具录一份，或显式传路径。 |
| `ValueError: .voice 必须为 16 kHz / mono / 16-bit PCM WAV` | 模板被其他软件改成了 44.1 kHz 或立体声，用录音工具重新导出。 |
| `ValueError: 不能用静音模板进行匹配` | 录制时游戏没出声，或录到了静音段。 |
| 完全不触发 | ① 阈值太高，试着 `threshold(0.6)`；② 模板与实际音效差异大，重录；③ 游戏没绑定对，确认 `PID`；④ 检查 `listen.error` 是否已停止监听。 |
| 频繁误触发 | 阈值调高到 `0.85`–`0.95`，并把模板剪辑得更贴近提示音本身（去掉前后杂音）。 |
| 按 F8 没反应 | 焦点在录音工具窗口上再按；热键是全局的，但被其他程序占用时会失效。 |
| 录制超时报 `目标进程没有及时提供音频数据` | 该时段目标进程没有输出声音，播放提示音后再录。 |

---

## 7. 已知限制

1. 需要系统支持进程独立 loopback（Build 20348+），低版本无替代方案。
2. 模板最长 10 秒、最短 0.04 秒；录音工具单次录制上限 10 秒。
3. 只采集目标进程**及其子进程**，若游戏把音频交给独立的外部进程播放，需要改为绑定那个进程。
4. 包内自带模板 `script_core/audio_manager/template.voice` 是 0.263 秒的示例片段，正式使用建议换成自己录制的完整提示音。
5. 动作线程异常会写入 `error` 并停止监听，需自行在脚本里检查。
