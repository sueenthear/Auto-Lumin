# OK Lumin 开发工具交接文档

## 1. 项目定位

`dev_tool/ok_lumin_tool` 是将以下两个旧工具合并后的统一工具：

- `dna_pos_tool`：目标窗口位置获取、区域定位和截图。
- `action_recorder_player`：全局键盘/鼠标动作录制与播放。

新工具使用 Tkinter 实现控制界面，不再依赖 Qt。原有的 `dna_pos_tool` 和 `action_recorder_player` 目录保持不变，后续维护统一以 `dev_tool/ok_lumin_tool` 为准。

当前工具面向 Windows 桌面环境，目标程序如果以管理员权限运行，本工具也需要以管理员权限运行。

## 2. 目录结构

```text
dev_tool/
├─ README.md                         # 简要说明
├─ 交接文档.md                        # 本文档
├─ 启动.bat                          # Windows 双击启动入口
├─ __init__.py
└─ ok_lumin_tool/
   ├─ __init__.py
   ├─ __main__.py                    # python -m dev_tool.ok_lumin_tool 入口
   ├─ main.py                        # Tk 主窗口、Notebook 和业务编排
   ├─ capture.py                     # 十字准心、区域框、窗口查找和截图
   ├─ runtime.py                     # 全局热键、录制器、播放线程和日志
   ├─ model.py                       # .stepscript 格式和动作规范化
   └─ requirements.txt               # 运行依赖
```

截图不会保存到 `dev_tool` 内，而是保存到启动时当前工作目录下的 `screenshot` 文件夹。

## 3. 安装与启动

建议使用 Python 3.10 或更新版本和 `uv`，并在项目根目录执行：

```powershell
uv sync --locked
uv run python -m dev_tool.ok_lumin_tool
```

也可以从任意工作目录双击：

```text
dev_tool\启动.bat
```

批处理文件按自身所在路径定位项目根目录，将 `uv` 环境固定到项目 `.venv`，执行 `uv sync --locked`，调用该环境的 `activate.bat` 后启动 `pythonw.exe`。它不依赖全局 Python 的包，也不会依赖启动前的当前工作目录。启动失败时会在命令行窗口显示英文错误并暂停。

### 3.1 依赖

项目依赖统一在根目录 `pyproject.toml` 声明并由 `uv.lock` 锁定。运行 `uv sync --locked` 会安装 `script_core` 与开发工具共同需要的依赖；Windows 上还会按平台条件安装 `pywin32`。不要使用系统 Python 安装另一套依赖后再启动工具。

`dev_tool/ok_lumin_tool/requirements.txt` 仅供不使用 uv 的独立 pip 环境参考；项目启动脚本不会读取该文件。

如果目标程序使用管理员权限，请用管理员权限打开 PowerShell 或直接以管理员身份启动本工具。否则可能出现窗口查找、全局监听或动作播放权限不足。

## 4. 界面结构

主窗口标题为 `OK Lumin 开发工具`，默认大小为 `980x720`，最小大小为 `820x580`。主界面使用 `ttk.Notebook`，包含两个页面。

### 4.1 位置与截图

该页面只管理两个浮层：

1. **红色十字准心**
   - 默认透明度为 45%，左键拖动可移动准心。
   - 双击：复制当前位置到剪贴板。
   - 鼠标滚轮：调整透明度。
   - “从准心读取”：将准心当前位置同步到界面的 `X/Y` 字段。

2. **蓝色区域框**
   - 左键拖动：移动区域框。
   - 右键拖动：调整区域框宽高，最小尺寸为 `20x20`。
   - 左键双击：截取目标窗口客户区。
   - 右键双击：截取当前区域。
   - 鼠标滚轮：调整透明度。

控制面板中的“显示准心”和“显示区域框”可以分别隐藏/显示两个浮层。

### 4.2 目标窗口绑定

“可执行文件名”的默认值配置在 `dev_tool/ok_lumin_tool/config.json` 的 `default_target_exe` 字段：

```json
{
  "default_target_exe": "Lumin.exe"
}
```

配置文件缺失、无效或字段类型不正确时回退为 `EM-Win64-Shipping.exe`。点击“绑定窗口”后，工具会遍历可见窗口并按进程名查找第一个匹配的窗口句柄。输入框留空时使用 Windows 桌面句柄。

绑定成功后，两个浮层会根据已有的客户区坐标移动到目标窗口位置。窗口句柄显示在目标窗口区域中。

### 4.3 坐标语义

所有位置和区域坐标均以**绑定目标窗口客户区左上角**为原点：

- 十字准心：`X/Y` 表示准心中心点的客户区坐标。
- 区域框：`X/Y/W/H` 表示区域左上角坐标、宽度和高度。
- 未绑定窗口时，浮层使用屏幕坐标；绑定后，读取和截图使用目标窗口客户区坐标。

“应用到区域框”只应用区域框的 `X/Y/W/H`，不会移动独立的十字准心。“读取区域框”会将当前区域框位置和尺寸写回界面字段。

## 5. 截图行为

截图默认写入：

```text
当前工作目录\screenshot\
```

文件名格式：

- 全窗口：`YYYY-MM-DD_HH-MM-SS.png`
- 区域：`YYYY-MM-DD_HH-MM-SS(x,y,w,h).png`

截图前工具会临时隐藏两个浮层，避免浮层内容进入截图，截图结束后恢复原来的显示状态。

“截取整个窗口”实际截取的是目标窗口**客户区**，不是包含标题栏和边框的完整 Windows 窗口。区域截图也基于客户区坐标换算为屏幕截图范围。

## 6. 动作录制与播放

### 6.1 录制内容

录制器记录：

- 键盘按下：`key_down`
- 键盘抬起：`key_up`
- 鼠标按下：`mouse_down`
- 鼠标抬起：`mouse_up`
- 旧版本兼容的瞬时鼠标点击：`click`

`mouse_down` 和 `mouse_up` 分别保存实际发生时间，因此可以记录并回放鼠标长按时长。开始录制时已经按住的按钮不会自动补一个按下事件；录制期间按下但停止前未抬起的按钮会在停止时补 `mouse_up` 并标记 `repaired: true`。鼠标点击支持：

- `left`
- `right`
- `middle`
- `x1`
- `x2`

录制不保存鼠标移动，也不保存鼠标坐标。因此播放鼠标按钮动作时，会在播放瞬间的当前鼠标位置执行。

`F8`、`F9`、`F10` 是控制热键，不会写入录制动作。

### 6.2 控制键

- `F8`：空闲时开始当前模式；暂停时继续。
- `F9`：暂停/恢复录制或播放。
- `F10`：终止录制或播放。

界面中的按钮也提供相同功能。全局热键默认在窗口初始化时尝试注册，也可以通过“全局快捷键已启用”按钮手动禁用或重新启用。

如果其他程序已经占用 `F8/F9/F10`，整组热键注册可能失败。此时仍可使用窗口内的按钮，状态栏会显示失败原因。

### 6.3 录制生命周期

开始新录制时：

1. 清空当前动作列表。
2. 创建一个默认脚本路径，例如 `steps-a1b2c3d4.stepscript`。
3. 启动 `pynput` 键盘和鼠标监听器。
4. 使用 `time.perf_counter_ns()` 记录相对时间戳。

停止录制时：

1. 停止接收新动作。
2. 对仍处于按下状态的键盘按键追加 `key_up`，对鼠标按钮追加 `mouse_up`，并标记 `repaired: true`。
3. 将监听器的 `join()` 放到后台清理线程，避免阻塞 Tk 主线程。
4. 将动作规范化并刷新动作表。

### 6.4 播放生命周期

开始播放前会再次调用 `normalize_actions()`。播放线程：

- 使用相对纳秒时间戳和单调时钟等待。
- 键盘动作通过 `pynput.keyboard.Controller` 注入。
- `mouse_down`/`mouse_up` 按各自时间戳执行，按住时长由两者的时间差决定；旧版 `click` 仍按瞬时点击兼容。
- 暂停时阻塞在 `resume_event`。
- 终止或异常退出时释放仍处于按下状态的键盘按键和鼠标按钮。
- 通过线程安全队列通知 Tk 主线程更新当前动作选中行和状态栏。

不要在 `runtime.py` 的后台线程中直接操作 Tk 控件。所有后台事件必须写入 `event_queue`，由 `main.py` 中的 `root.after()` 轮询处理。

## 7. `.stepscript` 格式

脚本是 UTF-8 编码的 JSON 文件，扩展名为 `.stepscript`。当前格式如下：

```json
{
  "format": "ok-lumin.stepscript",
  "version": 2,
  "timestamp_unit": "relative_ns",
  "info": {
    "duration_ns": 1000000,
    "action_count": 2
  },
  "actions": [
    {
      "type": "key_down",
      "key": "a",
      "timestamp_ns": 0
    },
    {
      "type": "key_up",
      "key": "a",
      "timestamp_ns": 1000000
    }
  ]
}
```

### 7.1 动作字段

键盘动作：

```json
{"type": "key_down", "key": "ctrl", "timestamp_ns": 0}
{"type": "key_up", "key": "ctrl", "timestamp_ns": 100}
```

鼠标长按：

```json
{"type": "mouse_down", "button": "left", "timestamp_ns": 200}
{"type": "mouse_up", "button": "left", "timestamp_ns": 1200200}
```

以上两个事件的时间戳差值就是长按时长。旧脚本中的 `click` 事件仍兼容，播放时作为瞬时点击处理。

支持的鼠标按钮为 `left`、`right`、`middle`、`x1`、`x2`。

### 7.2 规范化规则

`model.py` 的 `normalize_actions()` 会：

- 按 `timestamp_ns` 排序。
- 将首个动作的时间戳归零。
- 验证动作类型、按键名、鼠标按钮和时间戳。
- 为文件结尾仍未释放的键追加 `key_up`。
- 为文件结尾仍未释放的鼠标按钮追加 `mouse_up`。

当前只支持 `version: 2` 和 `timestamp_unit: relative_ns`，不兼容旧版 v1 脚本。

## 8. 代码维护入口

### `main.py`

负责：

- 创建 Tk 根窗口。
- 构建 Notebook 和两个页面。
- 连接按钮、字段和状态栏。
- 通过 `root.after(40, _poll_events)` 消费后台事件。
- 管理录制、播放、脚本打开/导出和窗口关闭流程。

修改界面布局、按钮行为或事件调度时，优先从这里开始。

### `capture.py`

负责：

- 创建两个独立的 `tk.Toplevel` 浮层。
- 按进程名查找窗口句柄。
- 在屏幕坐标和目标客户区坐标之间换算。
- 处理拖动、缩放、透明度和截图。

如果修改坐标逻辑，需要同时检查：

- `client_origin()`
- `sync_overlay_to_data()`
- `sync_data_to_overlay()`
- `apply_region_data()`
- `_screenshot_bbox()`

不要重新为每种颜色增加独立区域浮层。当前设计明确只有一个十字准心和一个区域框。

### `runtime.py`

负责：

- Windows F8/F9/F10 全局热键注册。
- `pynput` 全局键盘/鼠标监听。
- 后台播放线程。
- 按键释放清理。
- `%LOCALAPPDATA%\OkLuminTool\logs\ok-lumin-tool.log` 日志。

该模块不应导入 Tk 控件，也不应从后台线程直接调用 Tk 方法。

### `model.py`

负责 `.stepscript` v2 的保存、加载、校验、规范化和动作显示文本。修改脚本格式时必须同步更新读取校验、保存字段、文档和测试。

## 9. 日志与故障排查

日志文件：

```text
%LOCALAPPDATA%\OkLuminTool\logs\ok-lumin-tool.log
```

日志使用 `RotatingFileHandler`：

- 单文件最大约 2 MB。
- 最多保留 3 个备份。
- 记录热键、录制、播放和异常信息。

常见问题：

### 9.1 找不到目标窗口

- 确认输入的是进程名，例如 `EM-Win64-Shipping.exe`，不是窗口标题。
- 确认目标程序已经启动并且有可见窗口。
- 如果目标程序以管理员权限运行，使用管理员权限启动本工具。
- 需要使用桌面句柄时清空可执行文件名输入框。

### 9.2 截图失败

- 先点击“绑定窗口”。
- 检查目标客户区尺寸是否有效。
- 检查 `Pillow` 和 `pywin32` 是否安装。
- 检查当前工作目录是否有写权限。
- 多屏或 DPI 缩放环境下，优先确认工具和目标程序使用相同权限级别。

### 9.3 全局热键不可用

- 查看状态栏和日志文件中的错误。
- 检查其他工具是否占用了 `F8/F9/F10`。
- 关闭其他可能注册全局热键的程序后重新启用。
- 热键不可用时仍可使用界面按钮。

### 9.4 播放动作不符合预期

- 播放前将鼠标移动到目标点击位置。
- 确认目标窗口处于正确的前台状态。
- 录制器不保存鼠标坐标，无法自动恢复录制时的鼠标位置。
- 检查脚本中的 `timestamp_ns`、`key` 和 `button` 字段。
- 检查日志中是否有 `playback failed` 或不支持按键错误。

在项目根目录运行：


1. 窗口启动后存在两个浮层。
2. `位置与截图` 和 `动作录制与播放` 两个 Notebook 页面可以切换。

## 11. 后续开发注意事项

- 保持原有 `dna_pos_tool` 和 `action_recorder_player` 不变，除非明确需要迁移或删除旧工具。
- 新功能优先加入 `dev_tool/ok_lumin_tool`，不要重新引入 Qt 依赖。
- 不要在后台线程直接更新 Tk 控件。
- 修改坐标换算时必须同时验证未绑定状态、绑定状态、多屏和 DPI 缩放场景。
- 修改 `.stepscript` 结构时必须同步更新 `model.py`、文档和测试。
- 录制停止和播放异常路径必须确保按键释放，避免目标程序遗留按键按下状态。
- 不要把截图、日志、临时脚本或生成的测试缓存提交到源码目录。
